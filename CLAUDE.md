## What Hawk2UI Is

Hawk2UI builds desktop applications and embeddable audio-plugin editors (VST3/CLAP/AU) from web-like authoring primitives — **without** shipping Chromium, embedding a WebView, or requiring JUCE. The whole rendering/layout/text/scripting stack is native Rust; app authors write TypeScript + CSS + a manifest, not Rust.

Two host surfaces share one engine:
- **desktop** — owns native OS windows via `winit`.
- **plugin** — an editor surface embedded in a DAW-owned parent window via `baseview`.

(The root `README.md` predates the implementation and still claims "research phase / no runtime code accepted" — that is stale. The workspace contains the shipping engine.)

## Build, Test, and Verify

Cargo workspace, edition 2024, MSRV 1.95. Use plain `cargo`/`git` in commands — a local hook transparently rewrites them to `rtk` for token savings, so committed docs and your invocations should never hard-code `rtk`.

Two gates mirror CI. Prefer the xtask entry points (they run the scripts):

| Gate | Command | Covers |
|------|---------|--------|
| **Fast** (before every commit) | `cargo run -p xtask -- check-fast` (= `bash scripts/check-fast.sh`) | fmt check · `cargo check` · workspace tests · `api_contract` + `domain_test_templates` filters · smoke apps |
| **Full** (before release) | `cargo run -p xtask -- check` (= `bash scripts/check.sh`) | adds clippy `-D warnings` · `source_to_render` integration · `render_baseline` bench · `cargo doc` · `cargo deny` · whitespace |

Release readiness: `cargo run -p xtask -- release-check [--version-only|--packages-only|--changelog-only]`.

Targeted tests (these filter names are not discoverable from file paths):
- `cargo test --workspace api_contract` — API contract conformance
- `cargo test --workspace domain_test_templates` — per-domain spec templates
- `cargo test --test source_to_render` — end-to-end source→rendered-scene integration
- `cargo test -p hawk2ui-smoke --test smoke_apps` — desktop/plugin smoke fixtures
- `cargo test -p <crate>` (optionally `… <name>`) — single crate / single test

Lint posture is strict and gating: clippy `all` + `pedantic` are `warn` workspace-wide but CI runs `-D warnings`, so new code must pass pedantic clean. Dependency policy is enforced by `cargo deny check` (`deny.toml`).

## The CLI (`hawk2ui-cli`)

The end-user authoring tool. Subcommands (exit codes: `0` ok, `2` usage, `10` validation, `11` verification, `12` runtime):
`new`, `run`, `dev`, `validate`, `build-dev`, `build-release`, `verify-artifact`, `run-desktop`, `package-plugin` (CLAP/VST3/AU/standalone), `export-schemas`, `diagnostics`, `explain`.

`hawk2ui dev` is a native hot-reload loop (`crates/hawk2ui-cli/src/dev_loop.rs`): a `notify`-backed watcher classifies each changed file (manifest / style / asset / script / runtime-tree) into the narrowest reload action — style patch, asset-cache invalidation, runtime-tree patch, script rebuild, or full rebuild. A manifest change always forces a full rebuild.

## Architecture (crate layering)

A project — `manifest.hawk.toml` + a TS entry + CSS + assets (see `examples/desktop-basic` and `examples/plugin-synth-editor`) — flows through the build pipeline into a signed sealed artifact that a host loads and runs. The ~34 crates are layered by dependency direction:

- **Foundation** — `api` (public contracts, diagnostics, source spans) · `platform` (capability-scoped fs/net/clipboard/secrets/db) · `compat` (compatibility matrix).
- **Schema** — `schema` (product model, manifests, targets, capabilities) · `security-model` (threat registry, trust validation) · `core` (thin facade re-export).
- **Engine** — `style` (typed properties, tokens, CSS compiler) · `text` (`parley`/`swash`/`fontdb`: shaping, bidi, glyph cache, hi-DPI) · `layout` (`taffy` flexbox+grid + text-measure bridge) · `render` (retained scene records, backend boundary) · `assets` (decode/validate/hash) · `render-skia` (`skia-safe` renderer backend).
- **Runtime** — `runtime` (script loading, host bindings, event dispatch, scheduling, lifecycle) · `script` (`boa_engine` executes JS; `oxc_*` parses/transforms TypeScript).
- **Authoring** — `authoring` (typed component/state/event model) and adapters `framework-{react,vue,svelte,solid}` (each depends only on authoring/runtime/style).
- **Hosts** — `host` (surface contracts) · `host-winit` (desktop) · `host-baseview` (embedded plugin editor).
- **Plugin formats** — `plugin` (format-neutral editor/params/automation/state/presets) · `vst3` · `plugin-adapters` (emits CLAP/VST3/AU/standalone).
- **Tooling / QA** — `build`, `cli`, `a11y` (`accesskit`), `security`, `testkit`, `perf`, `conformance`, `framework-conformance`, `smoke`, `xtask`.

Build pipeline (`hawk2ui-build`): `BuildWorkspace::load()` reads `manifest.hawk.toml` → validates the manifest → discovers/validates/compiles sources, styles, and assets through ordered `BuildPipeline` phases → emits a `SealedArtifact` (ed25519-sha256 signed, schema-versioned) plus a `VerificationReport` used for release gating.

## Conventions That Will Trip You Up

- **`unsafe_code = "forbid"` workspace-wide.** The sole exception is `hawk2ui-host-baseview`, which sets `unsafe_code = "deny"` (overridable per call site) because embedding into a DAW window requires raw-window-handle FFI. Don't introduce unsafe elsewhere; in baseview, scope it tightly to the FFI boundary.
- **Spec-driven.** `specs/NNNN-*.md` are domain specs, `tasks/` are implementation task lists, `tasks/COVERAGE.md` maps specs→tasks→plans, and `docs/{decisions,development,research,security}/` hold ADRs, gate docs, and prior art. Non-trivial architecture changes should trace back to a spec.
