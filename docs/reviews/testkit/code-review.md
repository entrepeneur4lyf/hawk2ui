# Code Review — hawk2ui-testkit

**Reviewed at:** `5a042c51` · 2026-05-28 · working tree clean at review time
**Scope:** `src/{lib,fixtures,perf,security,templates,visual}.rs` + `tests/{domain_test_templates,fixture_helpers,security_rejections,visual_regression}.rs` + `Cargo.toml` (6 src files ~1.9k LoC / 4 test files ~590 LoC)
**Purpose:** Shared test support for the workspace: deterministic fixture catalogs, a `TempProject` scratch-dir helper, diagnostic/artifact equality assertions, a CPU pixel-diff visual-regression engine (RGBA snapshot compare + PPM/TOML artifact export), security-rejection fixture catalogs + a capability-coverage matrix, domain-test-template and performance-budget catalogs. Depends only on `hawk2ui-render` (for `Geometry`); dev-deps pull `hawk2ui-layout`/`-render-skia`/`-runtime` to drive a real Skia render in one test.
**Note:** Codex is concurrently committing hardening/remediation work; HEAD drifts (git HEAD is `5fecf2c4`). Findings reflect the SHA above and may overlap with in-progress fixes.

## Summary

The **assertion core is genuine, not stubbed**, and that is the part of a testkit that matters most. The pixel-diff engine does real work: `ImageComparisonMetadata::compare` (`visual.rs:191`) zips two `Vec<u32>` pixel buffers, computes a per-pixel max-channel `pixel_delta`, counts changed pixels, and accepts only when both `max_pixel_delta <= self.max_pixel_delta` and `changed_pixels <= self.max_changed_pixels` (`visual.rs:183`); `strict_rgba8()` sets both bounds to `0`, so the strict mode is exactly that — any single-channel-of-1 difference fails. `VisualImageSnapshot::from_pixels` (`visual.rs:300`) validates `width*height == pixels.len()` with checked arithmetic. `DiagnosticAssertion::assert_matches` and `ArtifactAssertion::assert_matches` (`lib.rs:250`, `lib.rs:329`) are real severity+rule / hash equality checks that return structured `Mismatch` errors, not always-`Ok`. `tests/visual_regression.rs` renders an actual runtime scene through `SkiaRendererBackend`, mutates one pixel, and asserts `changed_pixels == 1 && max_pixel_delta == 255 && !accepted` — a true end-to-end exercise of the strict path. No `todo!`/`unimplemented!`/`unreachable!`, no placeholder panics, no TODO/FIXME/HACK markers anywhere in the crate.

The substantive weaknesses are not vacuous assertions but **inert catalogs and one weak parallel assertion path**: (1) the **crate has zero consumers** — nothing in the workspace depends on it, so every "production baseline" is currently unverified intent; (2) the **security helpers verify nothing about security** — `SecurityRejectionFixtureSet::production_baseline()` hands out six fixture *path strings that point to files which do not exist in the repo*, and no code here loads them or checks the named rule fires; (3) the **string-command visual path** (`VisualSnapshot` + `matches_baseline`/`all_match`) compares recorded command *strings*, a weak proxy that cannot catch a pixel-level render regression, and its self-tests are tautological (`candidate = baseline.clone()`); (4) the **performance suite is purely record-only** — `PerformanceSuite`/`BenchmarkExpectation` store a budget name + optional `max_millis` but never time anything or assert a budget. Determinism is clean (see below). There is no correctness blocker — the real assertions are strict — but a consuming crate that leaned on the security baseline, the string-command path, or the perf suite would gain **false confidence**, and today there are no consuming crates at all.

## Completeness & implementation gaps

1. **The entire crate has no consumers** (`Cargo.toml`, workspace-wide). The crate doc says these are "helpers … for `Hawk2UI` tests," but a workspace-wide search for `hawk2ui_testkit` / `hawk2ui-testkit` and for every exported suite type (`SecurityRejectionFixtureSet`, `VisualRegressionSuite`, `DomainTemplateSuite`, `FixtureCatalog`, …) returns **only** the `members` entry in the root `Cargo.toml` — zero `use` sites and zero `[dev-dependencies]` edges from any other crate. Every `production_baseline()` is therefore self-asserted: the crate's own tests check that the baseline contains what the crate put in it, and nothing downstream consumes it. A testkit's value is the rigor it imposes on consumers; with no consumers, that value is currently zero. This is the dominant gap and recolors gaps (2)–(3): they are latent, not yet actively misleading anyone. → Either wire at least one real consumer (e.g. `hawk2ui-conformance`) onto these baselines, or treat the crate as pre-adoption scaffolding and say so in the docs.
2. **Security helpers do not test security; the referenced fixtures do not exist** (`security.rs:81` `production_baseline`). The set advertises `fixtures/security/undeclared-capability.toml`, `…/unsafe-asset.svg`, `…/invalid-manifest.toml`, `…/denied-host-api.toml`, `…/secret-leak.toml`, `…/unsupported-source-feature.hawk` with expected rules (`security.capability.denied`, `security.asset.unsafe`, …). A repo `fixtures/security/` directory **does** exist but holds a **disjoint** set (`malformed-manifest.toml`, `unsafe-vector.svg`, `oversized-asset.manifest`, …) — **none of the six advertised paths resolve to a real file** anywhere in the tree. Nothing in this crate reads a `SecurityFixture::path()` from disk, parses it, runs it through a pipeline, or verifies the named `diagnostic_rule` actually fires. So these are **string catalogs with dangling paths**, not security tests: a consumer that trusted "the security baseline is covered" would be trusting six pointers to nothing. `SecurityRejectionMatrix::require_capabilities` (`security.rs:168`) *is* a real check, but a shallow one — it verifies a capability **string** appears among the cases; it does not verify the fixture exists, that the rule is correct, or that any rejection occurs. Frame: real-but-shallow registry plus a completeness check, not security verification. (See Security.)
3. **`VisualSnapshot` string-command path is a weak proxy and is tautologically self-tested** (`visual.rs:626` `matches_baseline`, `visual.rs:725` `all_match`). `VisualSnapshot` (`lib.rs:354`) records a name, `(w,h)`, and a `Vec<String>` of free-text "commands" (`"draw-rect"`, `"draw-text:title:Amount"`). `VisualRegressionCase::matches_baseline` returns `self.baseline == self.candidate` — a derived `PartialEq` over those strings — and `VisualRegressionSuite::all_match` folds it. This cannot detect a real rendering regression: identical command *labels* with different rendered *pixels* pass. Both self-tests construct `candidate = baseline.clone()` (`lib.rs:480`, `tests/visual_regression.rs:42`), so they only ever assert `x == x`. This sits beside the genuinely strict `VisualImageSnapshot`/`compare` pixel path; the two coexist with no guidance that the string path is non-authoritative. → Document the string path as a metadata-shape check only, or drop it in favor of the pixel path.
4. **`PerformanceSuite` is record-only — it never times or enforces a budget** (`perf.rs:7`; `BenchmarkExpectation` at `lib.rs:434`). The suite stores `BenchmarkExpectation`s (budget name + optional `max_millis`) and exposes lookup by name, but there is **no** `run`/`measure`/`assert_within_budget` method anywhere — nothing executes a benchmark or compares an elapsed time against `max_millis`. The sole self-test (`benchmark_helper_records_budget_name`) only round-trips the getters. Same "records intent, does no real work" shape as the security helpers (gap 2): a consumer cannot use this to catch a performance regression; it is a budget *catalog*, not a budget *check*. → Add an enforcement entry point, or document it as a declaration-only registry.
5. **`ImageComparisonMetadata.color_space` is carried and exposed but never used in any decision** (`visual.rs:159`). It is stored, returned by `color_space()`, and asserted in a test (`== "rgba8-srgb"`), but `compare` (`visual.rs:191`) never consults it — there is no second color space, no conversion, no gating. Inert state on the comparison type. Minor, but it advertises a capability (color-space-aware comparison) the engine does not implement.

## Code quality & smells

- **Two parallel fixture registries with duplicated "missing" errors** (`FixtureRegistry` in `lib.rs:87` vs `FixtureCatalog` in `fixtures.rs:28`). Both wrap `Vec<TestFixture>`, both expose `require(&str) -> Result<&TestFixture, _>`, and both define a near-identical `MissingFixture(String)` error (`FixtureError` vs `FixtureCatalogError`). `FixtureCatalog` is the strict superset — it sorts on construction (deterministic order) and adds `require_kind`. `FixtureRegistry` is the unsorted, kind-blind subset, used only by a `lib.rs` unit test. This is duplication that will drift; `FixtureRegistry` reads as dead-weight precursor to `FixtureCatalog`. → Collapse to one.
- **`pixel_delta` / `compare` ignore the top byte; `count_changed_pixels` / `diff_pixel` use full-`u32` equality** (`visual.rs` `pixel_delta`, `count_changed_pixels`, `diff_pixel`). `pixel_delta` derives channels from bits 0–23 only (R/G/B), so `compare` is RGB-only, whereas `count_changed_pixels` (`!= reference_color`) and `diff_pixel` (`left == right`) compare all 32 bits. Under the **documented `0x00RRGGBB` contract** (confirmed: `SkiaFrameSnapshot::pixels` docs and `from_pixels` both specify the top byte is zero) this asymmetry is **latent** — the top byte is always `0x00`, so the two notions of "changed" coincide. Worth a one-line note that `compare` is defined on the low 24 bits; if a snapshot ever carried alpha in the high byte, `compare` would silently ignore it while the other two would not. Keep latent, do not overstate.
- **`count_changed_pixels` clamps a negative/huge `Geometry` by saturating `f32 as u32` casts** (`visual.rs:358`, `#[allow(clippy::cast_possible_truncation, clippy::cast_sign_loss)]`). `region.x.max(0.0).floor() as u32` etc. A negative origin floors to `0`; a huge width is later `.min(self.width)`. Behavior is safe (no panic, no OOB — the inner `usize::try_from` + `get` guard), but the silent clamp means an out-of-range region yields a count over the clamped sub-rect with no signal to the caller. Acceptable for a test helper; document the clamping.
- **"Sealed" naming without enforcement** — `ArtifactRecord` doc says "Sealed artifact metadata" (`lib.rs:267`) but it is a plain public struct with a public `new`. Cosmetic; "sealed" implies a guarantee not present.
- **`write_diff_ppm` dimension-mismatch branch emits an all-red buffer sized to the *baseline*** (`visual.rs` `write_diff_ppm`): on size mismatch it fills `vec![0x00ff_0000; baseline.pixels.len()]`. Reasonable as a "totally different" marker, but it silently discards the candidate's true size and is never reached by `compare` (which short-circuits dimension mismatch earlier into a report). Minor dead-ish edge.

## Testing (the crate's own tests)

- **Genuinely strong for the pixel path.** `visual_regression_renders_runtime_scene_with_skia_and_reports_pixel_diff_artifacts` builds a real `RuntimeViewTree`, renders via `SkiaRendererBackend`, flips one pixel, and asserts `changed_pixels == 1`, `max_pixel_delta == 255`, `!accepted`, plus a matching-baseline case that *is* accepted, plus `count_changed_pixels > 0` over the background. `visual_regression_writes_report_baseline_candidate_and_diff_artifacts` writes real PPM/TOML to a temp dir and asserts the diff PPM has a non-`"0 0 0"` line and the report says `failed_count = 1`. These would catch a regression in the comparison engine. `fixture_helpers_temp_project_writes_files_and_cleans_up_on_drop` verifies real FS round-trip and Drop cleanup.
- **Tautological / coverage-shaped tests elsewhere.** `visual_regression_records_snapshot_and_image_comparison_metadata` clones the candidate from the baseline, so `all_match()` is `x == x` (masks gap 3, and only positively asserts `accepts(0,0)` true / `accepts(1,0)` false). The `*_covers_required_fixture_families` / `provide_every_required_domain_template` tests assert the baseline contains the kinds the baseline was built from — shape checks, not behavior. They do **not** assert the referenced fixture *files* exist (which, for security, they do not — gap 2).
- **Coverage gaps:** no test for `FixtureCatalog::require_kind` returning `KindMismatch`; no test for `VisualImageSnapshot::from_pixels` `PixelCountOverflow`/`PixelCountMismatch` error paths; no test that `DiagnosticAssertion`/`ArtifactAssertion` return their `Mismatch`/`HashMismatch` errors (only the happy `Ok` path is exercised); no test that any advertised security fixture resolves on disk.

## Determinism

**Clean — no leakage.** All catalogs are `Vec`-backed and iterated in insertion order; `FixtureCatalog::new` additionally sorts by name (`fixtures.rs:34`), so even unordered input is deterministic. There is **no** `HashMap`/`HashSet` (no iteration-order nondeterminism), **no** randomness, and **no** time/PID influence on any fixture *data* or comparison result. The only time/PID use is `TempProject`'s `unique_name` (`fixtures.rs:137`), which folds `SystemTime` nanos + `process::id()` into the scratch **directory name** — that is correct (you *want* unique, collision-free temp dirs), not a determinism defect in fixtures or assertions. PPM/TOML artifact payloads are byte-deterministic functions of their inputs (`escape_toml_string`, `sanitize_artifact_name` are pure). The crate's determinism claim holds.

- **Deviation (Low):** this crate carries **no** `*_workspace_filter_marker` test (the marker that `hawk2ui-a11y`/`-smoke`/`-framework-conformance` include for conformance filter gates). If those gates enumerate per-crate markers, this crate is invisible to them — same deviation noted for `hawk2ui-assets`.

No `From`→`Diagnostic` bridge exists and none is expected here.

## Security

The trust boundary for a testkit is narrow: it ingests no untrusted bytes at runtime and derives **no** Serde anywhere (no `Deserialize` attack surface). `#![forbid(unsafe_code)]` holds — there is no `unsafe` and no deviation.

- **"Security helpers" do not enable real security testing — false-assurance risk** (`security.rs:81`, `security.rs:168`). This is the security-relevant finding. `SecurityRejectionFixtureSet`/`SecurityRejectionMatrix` produce *catalogs of strings* (capability name, fixture path, expected diagnostic rule). Nothing here executes a security boundary: no file is read, no manifest/source/asset is run through a validator, no rejection is observed, no rule is asserted to fire. Worse, the six advertised fixture paths (`fixtures/security/undeclared-capability.toml`, `unsafe-asset.svg`, …) **do not exist** in the repo (the real `fixtures/security/` holds a disjoint set). A consuming crate that treated `production_baseline()` as "the security rejection surface is covered" would have **false assurance**: the coverage is over names, and the names point at nothing. `require_capabilities` is a real-but-shallow check (capability-string presence only). **Medium** — it misrepresents test coverage of security properties; mitigated only by gap 1 (no consumer is currently fooled).
- **No insecure defaults baked into fixtures that consumers would copy.** The fixtures carry no embedded credentials, no permissive capability grants, no "allow-all" sample manifests — they are inert path+rule metadata. The one embedded asset (`ONE_BY_ONE_PNG` in `tests/`) is a benign 1×1 PNG. No copy-paste-insecure pattern. Clean.
- **`TempProject` writes under `std::env::temp_dir()` with a PID+nanos name and `remove_dir_all` on Drop** (`fixtures.rs:90`, `fixtures.rs:132`). Names are unique and non-predictable enough for test use; `write_file` (`fixtures.rs:113`)/`read_to_string` join a caller-supplied relative path under the root with no traversal guard, so a caller passing `../` escapes the sandbox — acceptable for a test-only helper driven by test-authored paths, but worth noting it is not a hardened sandbox. **Low.**
- **Panics-as-DoS:** not applicable — this is a test-only crate with no long-running surface; the assertion APIs return `Result` rather than panicking. The few `as u32` casts in `count_changed_pixels` are saturating and guarded by `try_from`+`get`, so no panic path. **Informational.**
- **Good:** real strict pixel comparison (`strict_rgba8` = 0/0 tolerance), checked pixel-count arithmetic (`u64` product → `usize::try_from`) on every snapshot constructor, deterministic byte-stable artifact output, and no `unsafe`/Serde/network/process-exec surface.
