## Remediation (2026-05-29) — contained subset

Fixed the real false-assurance weakness and added the one missing robustness test; left the architecture decision and the pure-cosmetic Lows untouched, recorded honestly. Verified: `cargo test -p hawk2ui-host` (19 passed) + `cargo clippy -p hawk2ui-host --all-targets -- -D warnings` (clean).

- **#3 — dead `requested_process_quit` false-assurance state (FIXED, Low).** `RecordingPluginAdapter.requested_process_quit` was write-once-`false` (initialized in `attach`, never assigned on any path), and `plugin_lifecycle_teardown_never_requests_process_quit` asserted `!adapter.requested_process_quit()` — a tautology that could never fail. Removed the dead field + accessor. The "a plugin editor never quits the host" invariant is **really** enforced structurally (`RequestQuit` is absent from `HostCapabilities::plugin()`, and no `PluginHostEvent`/`SurfaceWindowCommand` encodes a quit — `Close` destroys the editor, not the host), so the test now asserts that real guarantee: `!HostCapabilities::plugin().supports(HostCapability::RequestQuit)`. It fails if `RequestQuit` is ever added to the plugin capability set. (The only external caller was that one test — verified; smoke's `PluginEditorSmokeResult.requested_process_quit` is an unrelated hardcoded literal.)
- **#4 (real half) — `physical_size` robustness path untested (FIXED, Low).** Added `surface_metrics_physical_size_guards_non_finite_and_overflow`, exercising `scaled_physical_dimension`'s guards through `SurfaceMetrics::physical_size`: NaN/∞ scale → `(0,0)`, negative logical → `(0,0)`, `f64::MAX` dimensions → `(u32::MAX, u32::MAX)` (saturate, no wrap/panic). This was the one robustness-bearing numeric path with no coverage.

## Summary

This is a **genuinely-implemented contracts crate, not a stub or record-only scaffold.** The data records (`SurfaceMetrics`, `HostCapabilities`, the `SurfaceEvent`/`DesktopHostEvent`/`PluginHostEvent` enums, `HostPlatformHandle`) and the `RendererResizeBridge` carry real logic and are consumed by **both** real adapters: `WinitDesktopAdapter` (`hawk2ui-host-winit/src/lib.rs:943`) implements `DesktopHostAdapter`, `BaseviewPluginAdapter` (`hawk2ui-host-baseview/src/lib.rs:1973`) implements `PluginHostAdapter`, and both downstream test suites drive `RendererResizeBridge::{desktop,plugin}_event_to_target_request`. `HostPlatformHandle::validate_for` performs real ownership-compatibility checks; `SurfaceMetrics::physical_size` does real scale/overflow-guarded rounding; the bridge does real event→request mapping with exhaustive match arms (no `=> {}` swallow). The `Recording*` types are legitimate test stand-ins paired with the real impls in the sibling crates. No `todo!`/`unimplemented!`/`unreachable!`, no placeholder panics, no `unwrap`/`expect`/`panic` in `src/`, no TODO/FIXME markers, and `#![forbid(unsafe_code)]` holds.

The substantive weaknesses are narrow and **top out at Low–Medium**, which is the correct ceiling for a contracts crate: (1) the *unifying* `HostSurface`/`FramePresenter` traits — the crate's stated reason to exist ("common host surface API") — are implemented by **no production type** anywhere in the workspace and are never used as a generic bound or trait object, so they unify the two host kinds only on paper; (2) several delegating trait methods are one rename away from unbounded self-recursion; (3) a tautological test that cannot fail. The core job (shared records + bridge that both adapters actually use) is fulfilled; the trait-level unification is the smell.

## Completeness & implementation gaps

1. **The unifying `HostSurface` trait is exercised only by test doubles** (`surface.rs:203` `trait HostSurface`). A workspace-wide search finds **zero** production implementors of `hawk2ui_host::HostSurface` and **zero** uses as a bound (`<S: HostSurface>`), `&dyn`, or `Box<dyn>`. The only implementors are the three in-crate `Recording*` doubles (`RecordingHostSurface`, `RecordingDesktopAdapter`, `RecordingPluginAdapter`). The real adapters implement the *specific* `DesktopHostAdapter` / `PluginHostAdapter` traits instead and never touch `HostSurface`. So the trait the crate docs call the "Common host surface API" does not actually constrain or unify the two production host kinds — it is conformance-only scaffolding. Compounding this, `HostSurface::teardown(&mut self, reason: impl Into<String>)` uses `impl Trait` in argument position, which makes the trait **non-`dyn`-compatible** — it could not be used polymorphically (`&dyn HostSurface`) even if a caller wanted to, so its only possible use is as a static bound that nothing exercises. → Either route the real adapters through `HostSurface` (and drop `impl Into<String>` from the trait, e.g. take `String`/`Cow`, so it stays object-safe), or demote it to an explicitly test-only contract. Same applies to `FramePresenter` (`surface.rs:321`): no production implementor, only `RecordingFramePresenter`.
2. **`requested_process_quit` is write-once-false dead state** (`plugin.rs:127`, `:169`). The field is initialized `false` in `attach` and **never assigned anywhere** — no path sets it to `true`. `requested_process_quit()` therefore always returns `false` by construction. The field encodes an intended invariant ("plugin teardown must never quit the host process") but enforces nothing; it is the "records intent, does no real work" pattern. The corresponding test (#Testing) asserts the constant and so cannot fail. → Either remove the field, or have the plugin window-command/teardown paths actually consult/set it so the invariant is enforced rather than merely asserted.

## Code quality & smells

- **Cross-trait delegations rely on inherent-method resolution priority** (`desktop.rs:389` `DesktopHostAdapter::metrics`, `:422` `DesktopHostAdapter::set_focus`; `plugin.rs:272` `PluginHostAdapter::metrics`). Each `Recording*` type implements **two** traits that both declare the method (`HostSurface::metrics` *and* `DesktopHostAdapter::metrics`; likewise `set_focus`; `HostSurface::metrics` *and* `PluginHostAdapter::metrics`). These bodies call the unqualified `self.metrics()` / `self.set_focus(...)`, which resolves today only because an inherent method of the same name exists (`desktop.rs:302`, `:307`; `plugin.rs:180`) and inherent methods win over trait methods. Removing or renaming that inherent accessor would **not** cause silent recursion — `self.metrics()` would then have two equally-applicable trait candidates and fail to compile (`E0034`, "multiple applicable items in scope"). So this is build-time-safe, caught loudly by the compiler, not a latent runtime hazard. The real smell is the **inconsistency**: `HostSurface::set_focus` (`desktop.rs:331`) explicitly disambiguates its delegation (`DesktopHostAdapter::set_focus(self, focused)`) while three sibling delegations rely on resolution priority. → Qualify all cross-trait delegations explicitly for uniformity and resilience to refactors.
- **Structural capability vs runtime clipboard grant may read as a desync** (`desktop.rs:288`). `create_window` hardcodes `HostCapabilities::desktop()` (always including `ClipboardRead`/`ClipboardWrite`) independently of `config.clipboard`, so a window created with `ClipboardCapability::None` still reports `capabilities().supports(HostCapability::ClipboardRead) == true`. These are *plausibly two intentional layers* — `HostCapability` = "a desktop host can do clipboard" (static), `ClipboardCapability` = the runtime grant/mode, which `clipboard_available()` mutates and signals via `ClipboardCapabilityChanged`. The runtime-update path argues for "two layers," not "two sources of truth." Worth noting only because the distinction is undocumented: a conformance check that reads `capabilities()` as the authority on whether clipboard is *currently* usable would be misled. → Document the layering, or have `capabilities()` reflect the current grant.
- **Three near-identical `*_event_to_update_request` wrappers** (`resize_bridge.rs:98`, `:157`, `:204`). Each is `let request = self.*_to_target_request(...)?; Some(HostSurfaceUpdateRequest::new(request.metrics, request.clone(), request.reason))`. Acceptable given the three distinct event types, but the body is copy-pasted verbatim three times; a single private helper `target_to_update(request)` would remove the duplication.
- **`RecordingPluginAdapter::request_window_command` final arm is a silent `=> {}`** (`plugin.rs:246`). `SurfaceWindowCommand::SetMode(_)` on a torn-down editor falls through to `{}`. This is *correct* (post-teardown events are intentionally ignored crate-wide), not an inert stub — calling it out only to confirm it is deliberate, mirrored by the `accepts_host_event()` guard pattern used consistently elsewhere.

## Documentation

- Strong: crate-level `//!`, every public type, variant, method, and trait method documented. The one fallible function, `HostPlatformHandle::validate_for` (`platform.rs:176`), carries an accurate `# Errors` section. No undocumented public items.
- **Missing thread-affinity documentation (informational).** These are GUI-surface records consumed by a UI/main-thread adapter and an embedded-editor adapter. Nothing in the contract documents that these types are GUI-thread-affine and must not be driven from a realtime audio thread. No type here actually crosses the audio/UI boundary (see Security), so this is a doc gap, not a safety hole — but for a framework whose plugin editors coexist with a realtime audio thread, the host-surface contract is the natural place to state the affinity expectation.
- Minor: `requested_process_quit()` (`plugin.rs:169`) is documented as "Returns whether the adapter requested process quit" — technically true but misleading, since no path can ever make it return `true` (gap #2).

## Testing

- Good breadth for the happy paths: surface focus/repaint/resize/teardown/clipboard/presentation event recording; desktop window-state + input + DPI lifecycle; plugin attach/resize/DPI/repaint/input routing; host-driven show/hide idempotence; post-teardown event suppression; platform-handle system mapping + ownership-mismatch rejection (both directions, with `Diagnostic` conversion); and `RendererResizeBridge` maximize/DPI/resize request shaping incl. `force_redraw`/`invalidate_layout`/`logical_viewport`/`physical_size`.
- **False-confidence test (mirrors a11y `assert_serde`, assets cache test):** `plugin_lifecycle_teardown_never_requests_process_quit` (`tests/surface_lifecycle.rs:271`) asserts `!adapter.requested_process_quit()`. Since that field is initialized `false` and **never assigned** (gap #2), the assertion is a tautology that cannot fail — it documents an intended invariant but tests nothing. A meaningful test would drive a path that *would* request quit if the invariant were violated.
- **Coverage gaps:** (a) no test that the bridge's many `None` arms actually return `None` (e.g. `FocusChanged`, `RepaintRequested`, `ClipboardRequested`, `WindowCommandRejected`) — only the `Some` paths are asserted, so a future arm accidentally returning `Some` would pass; (b) no test of `SurfaceMetrics::physical_size` overflow/non-finite guards (`NaN`, negative, or `> u32::MAX` scale) — the one robustness-bearing numeric path is untested; (c) the `HostSurface`/`FramePresenter` traits are tested only via the recording doubles, never via a production type (gap #1); (d) no round-trip serde test despite every type deriving `Serialize`+`Deserialize` — only structural equality is asserted.

## Security

The trust boundary here is **`Deserialize`-able records** (every public type derives `Serialize`+`Deserialize`) plus the integer-encoded platform handles. `#![forbid(unsafe_code)]` holds; there is no `unsafe`. The dimensions that produced High findings in `hawk2ui-a11y`/`hawk2ui-assets` are **clean here, and that is itself the finding:**

- **No unbounded recursion / no stack-overflow DoS.** Unlike `hawk2ui-a11y` (whose `Deserialize`-able `A11yNode` tree recurses with no depth bound → High), every `Deserialize` type in this crate is **flat or fixed-depth** — `SurfaceMetrics`, the event enums, `HostPlatformHandle`, the `Recording*` structs hold only scalars, strings, fixed tuples, and `Vec<Event>` of non-recursive elements. There is no self-referential type and no recursive traversal in `src/`. Deserializing hostile input cannot drive deep recursion. Explicit contrast with a11y; **clean.**
- **No panic-as-DoS.** No `unwrap`/`expect`/`panic`/`assert`/slice-indexing in `src/`. `SurfaceMetrics::physical_size` → `scaled_physical_dimension` (`surface.rs:40`) already guards non-finite (`!is_finite() → 0`) and overflow (`>= u32::MAX → u32::MAX`) before the `as u32` cast, so even `NaN`/`inf`/huge deserialized metrics cannot panic or wrap. Good.
- **Threading (Low / informational, NOT a vuln).** These are GUI-surface records; the realtime audio thread is **not** a participant and **no type in this crate crosses the audio/UI boundary** — there is no shared mutable state, no interior mutability, no `Send`/`Sync` contract that an implementor could violate to race the audio thread. The honest gap is only that the contract does not *document* its GUI-thread affinity (see Documentation). This is informational, not an exploitable thread-safety hole.
- **`Deserialize` can reconstruct semantically-invalid states** (Low). The `Recording*` types derive `Deserialize` with private fields, so a crafted payload can produce states the constructors forbid — e.g. `RecordingPluginAdapter` with `lifetime = Live` but `visibility = Hidden`, or non-finite `SurfaceMetrics`, or an `events` history that never actually occurred. These are test doubles, so blast radius is small, but the derive admits states the runtime API guards against. Mirrors a11y's `A11yActionDispatcher`-with-fabricated-history observation.
- **Unbounded `events` Vec** (Low). All three `Recording*` types accumulate events with no cap or auto-drain (drain is caller-driven via `drain_events`). A long-lived recording adapter fed a runaway event stream is a slow memory-growth vector. Parallels a11y's unbounded `events` and assets' unbounded maps. Test-double scope limits severity.
- **Good — deliberate safe handle representation.** `HostPlatformHandle` captures every raw window handle as a `u64` ("captured as an integer for safe records"), never a raw pointer. This is exactly what keeps the contract `unsafe`-free and trivially `Send`/`Sync`/`Copy`; the unsafe pointer reconstruction is correctly pushed down into the host-baseview crate (the one place `unsafe` is permitted). `validate_for` correctly rejects the two incompatible (handle, ownership) pairings before any handle is acted on.
