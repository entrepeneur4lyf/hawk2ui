# Code Review — hawk2ui-render

**Reviewed at:** `5a042c51` · 2026-05-28 · **Remediated (contained subset):** 2026-05-29
**Scope:** `src/{lib,scene,layer,export,backend,assets,custom_surface,text}.rs` + `tests/render_export.rs` (8 src files ~3.3k LoC / 1 test file ~860 LoC)
**Purpose:** The backend-agnostic render model — retained scene graph records, deterministic paint-layer stack, scene-to-paint-command export, the renderer backend boundary trait, compiled-asset draw records, custom draw-surface integration records, and text contracts. The concrete backend is `hawk2ui-render-skia`.
**Note:** Findings reflect the SHA above. The dead/divergent `text.rs` module (#1) was **removed** 2026-05-29 — see the Remediation section. The paint-layer gradient/shadow/glow fidelity (#2) is part of the **bucket-(c)** effects pipeline, and the O(N²) scene-graph (#3) is a deferred perf refactor.

## Summary

This crate is **genuinely implemented, not a stub**, and most of it is load-bearing. The scene graph (`scene.rs`) does real work: parent/child structure with z-order paint ordering, ancestor invalidation with dirty-bounds accumulation and transform-aware bounds, a deterministic `diff` for repaint/cache decisions, and `effective_opacity` that multiplies subtree opacity groups along the ancestor path. The layer model (`layer.rs`), `export_paint_commands` (`export.rs`), and `SceneGraph` are consumed by the production runtime (`hawk2ui-runtime/src/view.rs` builds a `RuntimeSceneFrame` from them) and by conformance (`hawk2ui-conformance/tests/source_to_render.rs` asserts on `serialize_stable()`). The backend trait is real and constraining: `SkiaRendererBackend` implements both `RendererBackend` and `RendererCacheInvalidator` (`hawk2ui-render-skia/src/lib.rs:1538,1857`), and **every trait method is implemented by both `RecordingBackend` and `SkiaRendererBackend` — none is orphaned/unimplemented**. `RecordingBackend` is a legitimate test/reference backend, not a production placeholder. z-order/layer semantics are coherent: `children_sorted_by_z` and `push_paint_order` sort by `z_order` then tie-break on id, giving a deterministic front-to-back paint order. There are **no** `todo!`/`unimplemented!`/`unreachable!`, no placeholder panics, and no TODO/FIXME/HACK markers. `#![forbid(unsafe_code)]` holds and there is **no Serde** anywhere.

The substantive weaknesses are: (1) the entire **`text.rs` module is a parallel, unused, and partly-canned text model** — it has **zero** consumers outside this crate (the real text contract is `hawk2ui_text::TextLayout`, which skia and the runtime actually consume), it **diverges** from that contract (`max_width` vs `max_width_px`, no truncation), and its `measure()` returns canned `shaped: true` / fake linear width — with a test that asserts those canned values; (2) the **paint-layer model is lossy/record-only for gradients, shadows, and glows** — `GradientLayer` is a parameterless `Linear` tag and `ShadowLayer`/`GlowLayer` carry only a scalar, so real paint parameters travel out-of-band through the `apply_layer_effect(&str)` string instead; (3) the scene graph is **O(N²)** in the per-frame core path; (4) the `Diagnostic` bridge is implemented for only one of six error types. No correctness blocker on the desktop/runtime happy path; the defects are in an unused duplicated module, paint-model fidelity, per-frame complexity, and diagnostic-surface consistency.

## Remediation (2026-05-29) — contained subset

- **#1 — dead/divergent `text.rs` module (REMOVED).** It was a parallel text model with **zero** consumers outside this crate (the real contract is `hawk2ui_text::TextLayout`), and its `DeterministicTextMeasurer::measure` was **canned** — fake linear width (`char_count * average_glyph_width`), `shaped: true` hardcoded, `bidi_resolved` echoing the input flag with no actual shaping/bidi. Deleted the module, its `pub mod text;` / `pub use text::{…}` re-exports (confirmed zero external importers and absent from every conformance manifest), the crate-`//!` "text contracts" mention, and the three self-referential `text_contracts_*` tests that asserted the canned values. Per the mandate this **removes** false-assurance dead code rather than documenting it. `cargo test -p hawk2ui-render` (24 tests) + clippy `-D warnings` green after removal.

**Surfaced / deferred (NOT fixed — not contained):**
- **#2 — paint-layer gradient/shadow/glow are record-only (bucket-(c)).** `GradientLayer`/`ShadowLayer`/`GlowLayer` carry no real params; the payload travels out-of-band via the untyped `apply_layer_effect(&str)`. Giving them typed fields is part of the **effects pipeline** (the same item flagged in `render-skia` #1/#5 and `style`) — a design decision spanning style→runtime→render.
- **#3 — O(N²) scene graph (deferred perf).** Linear `index_of`/`node`/`entry` scans on the per-frame path; a `BTreeMap<SceneNodeId, usize>` index removes it. A perf refactor, not a correctness bug.
- **#4 + Low items unchanged:** partial `Diagnostic` bridge (only `BackendError`), stable-key delimiter collision, duplicated geometry validation, no dimension cap on `RecordingBackend` (Low — it allocates nothing; the real cap landed in `render-skia`).

## Completeness & implementation gaps

1. **`text.rs` is an unused, divergent, partly-canned parallel text contract.** Nothing outside this crate imports `DeterministicTextMeasurer`, `TextRenderInput`, `TextMeasureOutput`, `TextRenderTextError`, `render::FontRegistry`, `render::GlyphCacheKey`, or `render::LineBreakMode` (workspace grep: zero external hits). The contract the renderer actually consumes is `hawk2ui_text::TextLayout` / `TextLayoutInput` (skia's shaped-text path `draw_text_layout` at `hawk2ui-render-skia/src/lib.rs:806` consumes it; the trait's `draw_text(&str)` is only the bare-string fallback). The two models also **diverge**: render's `LineBreakMode::Wrap { max_width }` vs text's `Wrap { max_width_px }`, and render has no `TruncationMode`. Worse, `DeterministicTextMeasurer::measure` (`text.rs:181`) is **canned**: it returns `shaped: true` unconditionally and `bidi_resolved = input.bidi` without performing any shaping or bidi reordering, and computes width as `char_count * average_glyph_width` (a fake linear metric, not real shaping). Because nothing consumes it this is a structural/maintenance defect, not a live runtime bug — but it is the crate's clearest "records intent, does no real work" surface and it duplicates a real contract that lives elsewhere. → Delete `text.rs` and re-export from `hawk2ui-text`, or make it the single source of truth; do not keep a second divergent measurer.
2. **Paint-layer model is lossy/record-only for gradient, shadow, and glow** (`layer.rs:75,89,104`). `GradientLayer` is `enum { Linear }` with no stops, colors, or direction; `ShadowLayer` carries only `blur` (no color, no offset); `GlowLayer` carries only `radius` (no color). The backend's real shadow is parameterised out-of-band through the untyped `apply_layer_effect(&str)` string (e.g. `"shadow-rect:0,0,100,50:4,4:4:0,0,0,180"` in `tests/render_export.rs:452`). So for these three families the typed layer record cannot express what the renderer actually draws — the typed export is a degenerate placeholder and the real payload bypasses it via a stringly-typed side channel. → Give `Gradient`/`Shadow`/`Glow` real typed fields so the paint model is the source of truth rather than `apply_layer_effect` strings.
3. **`RendererBackend` under-constrains the real backend for the rich primitives.** The trait covers surface lifecycle, fill/stroke/path/clip/transform, opacity groups, cache handles, and dirty regions — all of which skia implements and the recording backend mirrors, so the boundary is genuinely useful for those. But the primitives the runtime relies on for premium output — shaped text (`draw_text_layout` consuming `TextLayout`), image/vector rect draws, and runtime-scene replay — are **inherent** `SkiaRendererBackend` methods, *not* trait methods. A second backend implementing only `RendererBackend` would get bare `draw_text(&str)`/`draw_image(&str)` and none of the rich path. The trait is coherent and used, but it is not the full contract the production renderer exposes. → Either document the trait as the minimal/legacy surface or lift the rich draws into the trait.
4. **`is_frame_due` modulo is on the absolute frame index, decoupled from `schedule_frame`** (`custom_surface.rs:179`). `scheduled = frame_index >= next_frame` and `frame_index.is_multiple_of(interval)` are independent; a surface with `schedule_frame(n)` where `n % interval != 0` is silently **not** due exactly at its scheduled frame `n` (it next fires at the following multiple). The test (`render_export.rs:811`) uses `schedule_frame(10)` with `interval 2` (`10 % 2 == 0`), so the edge is not exercised. → Phase the interval against `next_frame` (`(frame_index - next_frame) % interval == 0`), or document that the interval is on the absolute host clock.

## Code quality & smells

- **O(N²) scene graph on the per-frame path** (`scene.rs`). `index_of` (866), `node` (733), and `entry` (872) are all linear `iter().find` scans; `children_sorted_by_z`, `nodes_in_paint_order` → `push_paint_order` (878) calls `self.node()` **inside the sort comparator** (an O(log N) sort with an O(N) key lookup per comparison), and `diff` (829) does nested per-node lookups across both graphs. `effective_opacity` (786) and `invalidate` (708) re-resolve indices while walking. For a scene graph that is rebuilt and diffed every frame, this is super-linear in the hot path. → Back the graph with a `BTreeMap<SceneNodeId, usize>` (or store child references) so lookups are not linear.
- **Stable-key delimiter collision** (`layer.rs:281,337`, `export.rs:155`). Keys embed raw, unescaped content — `path({})`, `text({})`, `image({id})` — and `LayerStack::serialize_stable`/`PaintCommandList::serialize_stable` join with `|`. A `|` or `)` inside a path/text/asset-id value collides two distinct stacks onto the same serialized string. This is **not** purely cosmetic: `hawk2ui-conformance/tests/source_to_render.rs:70` asserts equality on `serialize_stable()`, so the serialization is a load-bearing identity. → Escape or length-prefix embedded content. Low-Medium.
- **Geometry validation reimplemented four times.** `validate_geometry` exists as a near-identical finite/non-negative check in `scene.rs:994`, `layer.rs:443`, `backend.rs:519`, and `custom_surface.rs:374` (the latter as `is_valid_geometry`). Likewise the finite-opacity-in-`0..=1` check recurs in `scene.rs`, `layer.rs`, and `backend.rs`. → Hoist a shared `Geometry::is_renderable()` / opacity helper.
- **Five near-identical diagnostic structs.** `LayerValidationError`, `BackendDiagnostic`/`BackendError`, `CustomSurfaceError`, `AssetDiagnostic`/`AssetError`, and `TextRenderTextError` are all `{ rule: String, message: String }` with the same constructor/accessor shape. Only `BackendError` bridges to `hawk2ui_api::Diagnostic` (see Conventions). → A single shared diagnostic type would remove the duplication and make the bridge uniform.
- **`AssetDrawRecord` discards everything but the id** (`assets.rs:282`). `from_compiled` validates a rich `CompiledAsset` then keeps only `asset_id`; kind, dimensions, sanitized flag, and backend requirements are dropped. By design (the renderer re-looks-up the compiled asset by id), but it makes the draw record a thin handle whose validation result is not carried forward. Minor.
- **`Stroke`/`RoundedRect`/`ShadowLayer`/`GlowLayer` expose public `f32` fields** that can hold NaN/Inf at construction; validity is only enforced later in `LayerKind::validate`. Construction-time invariants would be safer, but deferred validation before export is an acceptable pattern here.

No undocumented public items found.

## Security

The trust boundary here is **in-process render records built by trusted upstream code** (the runtime/layout/asset pipeline), *not* untrusted input. Critically, this crate derives **no Serde** on any type (confirmed by grep), so **a11y's High-severity finding does not transfer**: there is no `Deserialize`-able scene tree, and the only way to construct a `SceneGraph` is through the validating `SceneGraph::new` / `with_child` builder. `with_child` is the sole entry-adding mutator — it rejects duplicate IDs, requires an existing parent, and sets each node's `parent` exactly once at insertion (never re-parented) — so the graph is always a single-parent tree and **cycles cannot form via the public API**. `#![forbid(unsafe_code)]` holds; there is no `unsafe`.

- **Builder-bounded recursion** (`scene.rs:878` `push_paint_order`). Paint ordering recurses over `children`; the parent walks in `invalidate` (708) and `effective_opacity` (786) iterate ancestors. Because the tree is built only through the validating builder (no Serde, no cycles), recursion depth is bounded by the trusted construction path rather than by attacker input — so this is **Low**, not the High it would be over a deserialized tree. A depth cap or iterative traversal is still worth it for defense-in-depth against an accidentally pathological (deeply nested) UI tree. **Low.**
- **Unbounded `Vec` growth.** `SceneGraph.entries`, `RecordingBackend.commands`/`dirty_regions`/`cache_invalidation_keys`, and `SceneNode.effect_refs`/`invalidation_reasons` grow without a cap. Parallels the unbounded-`events`/`manifest` growth flagged in a11y/assets; a long-lived graph or recording backend is a slow memory-growth vector. **Low.**
- **Verbatim string pass-through.** Node IDs, layer keys, paths, text, and asset IDs are stored and formatted into stable keys without length bounds. Not an injection vector in-process (and `is_stable_identifier`/`is_valid_layer_key` constrain IDs/keys to `[A-Za-z0-9_-]`), but path/text/asset-id content is unbounded and unescaped — pairs with the stable-key delimiter-collision smell above. **Low.**
- **No upper bound on dimensions** (`backend.rs:497` `validate_surface_size`, `scene.rs:994`/`backend.rs:519` `validate_geometry`). Surface size is only checked non-zero and geometry only finite-and-non-negative — there is no ceiling, so `create_surface`/`resize_surface` with `u32::MAX × u32::MAX`, or a finite-but-enormous `Geometry`, passes every gate. *This* crate only records (it allocates nothing per draw), so there is no bomb here; but the `RendererBackend` contract does not require backends to bound `width × height` either, so the unbounded allocation lands in skia. This is the assets decode-bomb parallel, downgraded because render itself does not allocate. → Cap `width × height` (and geometry extent) at the trait/record boundary for defense-in-depth. **Low (downstream).**
- **Good input validation at the record boundary.** Geometry rejects non-finite and negative width/height (`scene.rs:994`, `backend.rs:519`); transforms must be fully finite; opacity (node and group) is finite-and-`0..=1`; DPI scale is finite-and-`>0`; surface dimensions must be non-zero. `Color` is four `u8`s, so **color NaN/Inf is impossible by construction** (no float color channels to validate). `CustomSurfaceDataSnapshot::new` caps realtime samples at **4096 finite values** at the plugin→UI-thread boundary — a genuine bound on the one place untrusted-ish realtime data enters. The recording backend records nothing for invalid inputs (`render_export.rs:524` asserts this).
- **No panics-as-DoS in src.** Indexing into `entries` is always guarded by a prior `index_of`/`entry` lookup; arithmetic uses `saturating_add`/`mul_add`; there is no `unwrap`/`expect`/`panic!` on a public path (only in tests). Float comparisons use bit-equality (`to_bits`) where determinism matters.
