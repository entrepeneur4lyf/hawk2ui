# Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement plugin format metadata, editor embedding, parameters, automation, state envelopes, presets, and realtime visual data transport.

**Architecture:** Keep plugin core data format-neutral, then add format adapters that map the same parameter, editor, state, and packaging records into CLAP, VST3, AU, and standalone targets. Realtime visual data uses preallocated non-blocking transport from audio processing to UI.

**Tech Stack:** Rust, format adapter crates selected by API contract plan, rtrb or ringbuf, serde, cargo test.

---

## File Structure

- Create: `crates/hawk2ui-plugin/src/lib.rs` plugin API exports.
- Create: `crates/hawk2ui-plugin/src/format.rs` format target records.
- Create: `crates/hawk2ui-plugin/src/editor.rs` editor embedding records.
- Create: `crates/hawk2ui-plugin/src/parameter.rs` parameter model.
- Create: `crates/hawk2ui-plugin/src/automation.rs` automation events.
- Create: `crates/hawk2ui-plugin/src/state.rs` state and preset envelopes.
- Create: `crates/hawk2ui-plugin/src/realtime.rs` realtime visual data transport.
- Create: `crates/hawk2ui-plugin/tests/plugin_behavior.rs` plugin tests.
